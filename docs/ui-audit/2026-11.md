# UI/UX audit 2026-11: summary

The first full audit under [docs/UI-UX-POLICY.md](../UI-UX-POLICY.md) (adopted 2026-11-15), done right after the
policy was adopted, as its section 3.1 asks. Every rule was assessed on every platform of both apps, in two passes by
fresh auditors: a blind pass 1, then an adversarial pass 2 that read pass 1's table and tried to break each result.
This page is the final record; the detailed findings, with evidence and `file:line`, are in the per-platform files
beside it:

## 1. What was audited, and how

- **Code:** main at 9eb5b09b (Walkdown 0.10.6). Walkdown Plant's content was not rebuilt: a build from 6f016e62 was
  used, with main's panel and HUD code.
- **Data:** synthetic only (the policy's rule Z1). Each run made its own server on 127.0.0.1 from the test fixtures:
  the sample sheet `importer/tests/vectors/kkp-sample.pdf`, the tag 11LAB70AA501 with long text and the Arabic
  fixture note `مضخة التغذية 11LAB70AA501 تعمل`, 20 marked tags waiting for approval, 20 tags in the review queue,
  10 to 20 sign-up requests, made-up users ("The Manager", "Tom Tester", "تالا Member"). Plant used its generic
  content only. The Learning list and course pages were never screenshotted for the repository (the plant courses'
  titles carry the plant's name).
- **Web:** Playwright 1.63 in Chromium, WebKit (standing in for Safari) and Firefox, headless: 14 screens at 412 × 915
  and 1280 × 800, light and dark, 200 % zoom (640 × 400) and 320 px width; ARIA snapshots, every target's bounds,
  computed colours and font sizes; probes for the keyboard, Escape, copy, offline, long tasks, reduced motion and a
  long sheet name.
- **GNOME:** the app in the private headless session (`apps/gnome/e2e/headless.sh`, never the desktop), light, dark,
  high contrast and Large Text 1.25; 84 screens with AT-SPI dumps (1,881 controls), a 40-press Tab walk through
  mutter's RemoteDesktop API. The desktop was checked unchanged before and after.
- **Windows:** the x86-64 build in the Windows 11 VM at 1280 × 800 and 100 % scaling; light, "dark" (the app setting),
  "High Contrast Black" and text size 150 %; UIA dumps with rectangles; Tab and Escape.
- **Android:** the debug APK on the Pixel 9 Pro XL emulator (Android 16, density 3.0), demo-mode status bar; light and
  dark, font scale 1.3 and 2.0, landscape, soft keyboard, Back, the app killed in the background, offline, taps beside
  a tag; uiautomator dumps (sizes in dp), `dumpsys gfxinfo`.
- **Plant, desktop:** every panel opened off-screen at 1600 × 900, and in the phone layout (UI scale 1.35, sizes in dp
  with the policy's factor 0.457); every visible Control's rect, font and colour; Plant run in the headless GNOME
  session with Godot's accessibility forced on (rule A5).
- **Pass 2** ran one extra web probe in the three engines and otherwise worked from pass 1's raw outputs and the code
  ("from code" in the per-platform files means read from the source, not seen on screen).

## 2. What was not checked, and why

- **Walkdown Plant on Android:** the arm64 build doesn't run on the x86-64 emulator (`INSTALL_FAILED_NO_MATCHING_ABIS`),
  and no Note 9 session was possible during the audit. As the policy's section 4 allows, the phone
  layout rendered on the desktop stands in: the "Plant Android" column below is that stand-in, plus what pass 2 read
  from the code (Back quits the app, PLANT2-2). Rules that need the phone itself are "Not checked": the Note 9's frame
  walk (P1), freezes and response times (P3, P3a). They wait for a phone session.
- **Pass 2 for Plant** was done separately ([pass2-plant.md](2026-11/pass2-plant.md)); the Plant part of
  pass2-gnome-plant.md was left unfinished and is not used.
- **Windows 10:** the kks-win10 VM was not run; every Windows result is from Windows 11 at 100 % scaling. Pass 2 lists
  from the code what may differ on Windows 10 ([pass2-android-windows.md](2026-11/pass2-android-windows.md), "Where
  Windows 10 may differ"): TLS 1.2 only, so join and sync errors carry Schannel's own wording (F2); the dark title bar
  attribute and the missing dark common controls (K6's fix needs testing there); the older contrast themes (K1); 125 %
  and 150 % scaling, the usual laptop default, which the layout doesn't handle (WIN2-4); a 40 px taskbar, which still
  leaves 820 px windows overflowing (R3).
- **Real screen readers and phones:** TalkBack's and VoiceOver's speech, Narrator, sunlight and gloves. The
  accessibility trees (uiautomator, ARIA snapshot, AT-SPI, UIA) and measured sizes stand in, as the policy accepts.
- **iPhone and Safari:** no iPhone here. WebKit-GTK under Playwright stands in; the safe-area findings (WEB-8,
  WEB2-13), the native select (WEB-12) and the 16 px field rule are from code and want a check on a real iPhone.
- **Smaller gaps** (each named in its file): GNOME at a 360 × 640 window and with reduced motion; Windows' photo
  mark-up, copy/paste and offline; web forced colours beyond one Chromium screenshot; Android's photo editor (no
  camera picture on the emulator); Plant's Workshop and the map's gestures on screen; P2 measurements outside the web.

Notes on single cells:

- **X1 on the web:** pass 1 left it Not checked; it is a Fail because the same count is named three ways across the
  clients (web, GNOME and Windows "Readings to review", Android "To review", GNOME's queue "Review queue"): a name
  that differs between clients fails on each of them (G20).
- **X2:** N/A everywhere: it judges a change that adds a feature, not a state.
- **K1 on Windows:** from code (pass 2: course text in a dark contrast theme, 1.30:1); it wants a screenshot to
  confirm.
- **K5 in Plant:** the HUD's status, time and distance labels over the 3D view have a thick black outline instead of
  a backing panel. That probably holds the contrast, but the rule's words ask for a panel; only the user can waive it
  (PLANT2-12).
- **R1 on Android** fails only for the tag panel's Close, which is being fixed elsewhere (section 6); Windows' R1 has
  that same in-progress part plus the 150 % layout (G13).
- **B1** is in progress for the admin approvals on every client (section 6); the cells stay Fail for what that work
  leaves out (the review queue, devices one by one, Plant's "Acknowledge all" count).
- **D2 in Plant** passes only because Plant has one destructive confirmation; `ui/widgets.gd` has no destructive
  button style, so the next one (PLANT-8's fix) needs it first.
- **D3 in Plant** passes from the code (typed text survives panels closing); the app being stopped was not checked.

The web fails the most rules because the most could be measured there (three engines, every size); most of its fails
have small fixes. GNOME passes the most of Walkdown's clients, thanks to libadwaita's own dialogs, toasts and type
scale. The fails shared by every Walkdown client are destructive actions without a question or Undo (G1), Back or
Escape dropping typed input (G2), drawing highlights under 3:1 (G5) and colour-only tag states (G6), raw error texts
(G7), and screen-reader names (G10).
